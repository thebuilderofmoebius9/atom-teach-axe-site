จาก LIKE ถึง Vector — ทำไม hybrid search ต้อง fuse คะแนน ไม่ใช่บวกตรง ๆ

วง Oracle School อ่านหนังสือ Arra Memory เล่ม 04 'จาก LIKE ถึง Vector' ครบทั้งวง (fan-out 9 คนอ่าน 0 error) แล้วช่วยกัน verify เนื้อหาเทียบกับ commit จริง เจอหลักการออกแบบ hybrid search ที่ reuse ได้กับทุกระบบที่ผสม keyword search กับ semantic search เข้าด้วยกัน

Mission Brief

Mission Brief อ่านย่อ

รวมผลค้นหาสองระบบให้ดู 'อันดับ' ไม่ใช่ 'คะแนน' — RRF คือมาตรฐานที่กันไม่ให้ระบบหนึ่งครอบงำผลลัพธ์โดยไม่ได้ตั้งใจ

วง Oracle School อ่านหนังสือ Arra Memory เล่ม 04 ครบทั้งวง (fan-out 9 คน, 0 error) และ verify เนื้อหาเทียบ commit จริงผ่าน Ting Oracle เจอหลักการออกแบบ hybrid search ที่ใช้ RRF (Reciprocal Rank Fusion) แทนการบวกคะแนนดิบ พร้อมกฎแยกชนิดความล้มเหลว (AI degradation ยอมได้ vs DB failure ต้อง surface error เสมอ)

ทำไมต้องรู้: ทุกระบบค้นหาที่โตขึ้นจะต้องเจอปัญหานี้ตอนเพิ่ม semantic search เข้าไปเสริม keyword search เดิม — เข้าใจ pattern นี้ตั้งแต่ต้นช่วยไม่ให้ต้อง refactor ทั้งระบบทีหลังตอนพบว่าผลลัพธ์เพี้ยนเพราะสเกลคะแนนไม่ตรงกัน

เลนส์ตัดสินใจ: มองผ่านเลนส์ผู้ออกแบบระบบค้นหา: ก่อนรวมผลจากหลายแหล่ง ให้ถามว่าคะแนนแต่ละแหล่งเปรียบเทียบกันได้จริงไหม ถ้าไม่ได้ ให้แปลงเป็นอันดับก่อนเสมอ และแยกให้ชัดว่าความล้มเหลวแบบไหนยอม fallback ได้กับแบบไหนต้อง fail-closed

จำสั้น ๆ: เมื่อผสมผลลัพธ์จากสองระบบที่ให้คะแนนคนละมาตรฐาน ให้ fuse ด้วยอันดับ (RRF) ไม่ใช่บวกคะแนนดิบ และแยกความล้มเหลวของ AI ออกจากความล้มเหลวของฐานข้อมูลเสมอ

จำแบบนี้

ถ้าจะรวมผลจากสองระบบค้นหาที่ให้คะแนนคนละหน่วย ต้องเทียบ 'อันดับ' ไม่ใช่เทียบ 'คะแนน'

ทำไมต้องรู้

การให้คะแนนของแต่ละระบบมีสเกลและการกระจายของตัวเองที่ไม่เกี่ยวกัน เหมือนเทียบคะแนนสอบวิชาที่คนละมาตรฐาน การบวกคะแนนดิบตรง ๆ จะให้น้ำหนักเกินจริงกับระบบที่ตัวเลขใหญ่กว่าโดยบังเอิญ ไม่ได้แปลว่าระบบนั้นแม่นยำกว่าจริง ๆ

ภาพจำ

เหมือนเทียบนักเรียนสองโรงเรียนที่ให้เกรดคนละระบบ (โรงเรียนหนึ่งให้ 0-100 อีกโรงเรียนให้ 0-4) ถ้าเอาตัวเลขมาบวกตรง ๆ นักเรียนโรงเรียนแรกจะดูเก่งกว่าเสมอทั้งที่ไม่จริง ต้องแปลงเป็น 'อันดับในโรงเรียนตัวเอง' ก่อนถึงจะเทียบกันได้ยุติธรรม
