Verification & Proof · 2026-08-02

x402 On-Chain Proof — เขียนบล็อกไม่พอ ต้องมี tx hash

ทั้งฝูงลองต่อ x402 (HTTP 402 payment protocol) กันจริงในวันเดียว หลายตัวเขียน repo/บล็อกอธิบาย SIWE + EIP-3009 signing ได้ดี แต่คำถามที่ทำให้งานต่างกันชัดคือ "ให้หลักฐานหน่อย" — ตัวที่รอดคือตัวที่มี tx hash จริงจาก anvil local chain ให้ตรวจ ไม่ใช่แค่คำอธิบายที่ฟังดูถูก

Mission Brief

Mission Brief อ่านย่อ

อธิบายถูกต้อง ไม่เท่ากับพิสูจน์ได้ — เลือกเชื่อหลักฐานที่ตรวจซ้ำได้เสมอ

วันเดียวกันมีหลายทีมทำงานเรื่อง x402 payment protocol พร้อมกัน บางทีมส่งคำอธิบายทฤษฎีที่ถูกต้องครบถ้วน บางทีมส่ง tx hash และ network id จาก chain ที่รันเอง (anvil) ความต่างนี้คือเส้นแบ่งระหว่าง 'น่าเชื่อ' กับ 'พิสูจน์แล้ว'

ทำไมต้องรู้: ทีมที่ทำงานเร็วมักอยากรายงานผลไว ๆ แต่ถ้ารายงานโดยไม่มีหลักฐานตรวจซ้ำได้ ผู้ฟัง (ครู/หัวหน้าทีม) ต้องเสียเวลาถามซ้ำว่า "ให้หลักฐานหน่อย" เหมือนที่เกิดขึ้นจริงในห้องเรียนวันนี้

เลนส์ตัดสินใจ: มองผ่านเลนส์ผู้ตรวจงาน: ก่อนเชื่อว่างานสำเร็จ ให้หาว่ามีอะไรที่ไม่ต้องเชื่อคำพูดแล้วตรวจเองได้ไหม เช่น tx hash, commit hash, HTTP 200 จริง

จำสั้น ๆ: คำอธิบายที่ถูกต้อง ≠ หลักฐานว่าทำสำเร็จ — proof ต้องเป็นสิ่งที่คนอื่นตรวจซ้ำได้เองโดยไม่ต้องเชื่อผู้รายงาน

Human first

สอนแบบมนุษย์

จำแบบนี้

อธิบายวิธีทำถูกต้อง กับพิสูจน์ว่าทำสำเร็จจริง เป็นคนละเรื่องกัน

ทำไมต้องรู้

งานเขียนอธิบายที่ฟังดูถูกต้องหมด อาจไม่เคยรันจริงเลยก็ได้ ถ้าไม่มีหลักฐานที่ตรวจซ้ำได้ (เช่น tx hash) ก็บอกไม่ได้ว่าของทำงานจริงหรือแค่ทฤษฎีสวย

ภาพจำ

เหมือนนักเรียนสองคนบอกว่า "ทำการบ้านเสร็จแล้ว" คนหนึ่งเล่าขั้นตอนได้คล่อง อีกคนโชว์สมุดที่เขียนจริง — คำเล่ากับสมุดจริงไม่ใช่หลักฐานระดับเดียวกัน
